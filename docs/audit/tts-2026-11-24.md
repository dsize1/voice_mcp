## 1. 摘要

## 7. 缺陷分类与优先级

| 类别 | 例 | 严重度 | 处置 |
|---|---|---|---|
| OOV 丢词 | iPhone、hometown、makes、universities、influenced | **S1** | 补 `tts-lexicon.txt` / `phoneme_codepoints`，再 3/3 验证 |
| 词表内读坏 | export（旧 1.0×）、That's、after | **S1** | 换已验证音色 + 140 wpm；必要时补词条/改写 |
| 语速超标 | s1–s8 全部 177–299 wpm；15/30 refs | **S2** | 用 140 wpm 重生成；`tts-verify` 纳入 WPM |
| 基线不可用 | country/thank/tokyo 回读不一致 | **S1** | `gop_baseline_valid=false`；禁止 Δ |
| 元数据/证据缺口 | 历史 baseline 无音频 | S3 | 以后落盘 baseline wav + valid + wpm |
| 单引擎不一致 | s2/s3/s8、多个 prompts | S2 | 人工/3 次复现复核，不直接判材料失败 |

## 8. 建议（按顺序）

1. **不要直接用 s1–s8 做听力计分**；保留原文件，另生成 `verified-140wpm` 版本（不覆盖原件）。
2. **补项目 lexicon**：优先 `hometown`、`makes`、`universities`、`influenced`、`that's`，以及 `iphone`、`export` 的已验证条目；每条走 `tts-verify --runs 3`。
3. **prompt 全部重跑**：OOV 补词后，用 `tts-verify --runs 3`；未通过进 quarantine，不进教学/听力。
4. **baseline**：默认音色从 af_heart 改为已验证音色（如 am_michael/bf_emma）；保留 `gop_baseline_valid` 闸门；后续落盘 baseline 音频。
5. **批量生成管线**接入 `tts-verify`：任何 `tts_verified` 资产必须带 ASR/音素/WPM/3 次证据。

## 11. s5 前置 schwa 伪影（已定位，未采用裁切）

用户听出 s5 的 af_heart 版在 “Can you” 前多了一个 “a”。波形对比：

| 版本 | 起始 |
|---|---|
| af_heart 1.0× / 0.8× / **0.7×** | 连续进入 Can，**无孤立前置音** |
| af_heart 0.65× / WPM 140 | **0.10–0.16 s 低幅浊音** → 0.17–0.25 s 静音 → 0.26 s Can |
| am_michael 140 | 0.15 s 直接进入 Can |

结论：伪影只出现在 af_heart 的**某个慢速点**（约 0.63–0.65×/140 wpm），不是文本或词典错误。
处置：s5 改用 **af_heart 0.7×（159 wpm，仍在 130–160）**；3 次双 ASR + 音素审计
（`phone_min 1.85–2.11`）全部 pass。136 wpm 伪影版保留为 `s5_af_heart_artifact.wav`。

**明确不采用“裁掉前 0.16 s”**：那只是诊断手段；对所有 af_heart 无脑裁切会误伤真实语音。
正确策略是：遇到 onset 伪影 → 换速度/换音色并重新验证，而不是修音频。

**2026-11-24 用户人耳确认：af_heart 0.7× 的 s5 正确，作为最终版本。**
