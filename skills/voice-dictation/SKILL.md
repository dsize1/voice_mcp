# 语音录入 / 听写

把口语变成**可直接使用的文字**。与 `ielts-speaking-coach` 的区别：这里不纠音、不打分，只求准确 + 好读。

## 1. 流程

```
① 拿到音频 → ② 转写 → ③ 清理 → ④ 交付（+留证）
```

**① 拿到音频**（三选一）

| 情况 | 做法 |
|---|---|
| 有麦克风（`mcp__voice__status` 的 `mic` 非 null） | `mcp__voice__record(max_sec=60, transcribe=true, lang="auto")` |
| 用户用系统录音机录的 | `mcp__voice__transcribe(path="last")`（`voice-cli watch` 会自动导入新录音） |
| 用户给了文件路径 | `mcp__voice__transcribe(path=绝对路径)` |

**② 转写**：语言不用猜，直接 `lang="auto"`。中英混说建议加 `engine="whisper"`（对 code-switching 更稳）。

**③ 清理规则**（这是本 skill 的核心，不要跳过）

| 现象 | 处理 |
|---|---|
| `um / uh / er / 嗯 / 呃` | 删除；若连续出现 3 次以上，改为一个破折号 `——` 表示犹豫 |
| 同词连续重复（`the the`、`我我`） | 合并为一个 |
| 自我修正（`I mean`、`或者说`、`不对`） | 删除前半句，只保留修正后的内容 |
| 口语句式（`you know`、`like`、`就是`） | 删除，除非是引用或语气需要 |
| 数字（`three hundred`、`三百`） | 按用途决定：技术/金额/日期保留阿拉伯数字，叙述保留汉字（中文）/英文单词（英文） |
| 术语/缩写（`A P I`、`m c p`） | 合并为正确写法（API、MCP）；不确定就问用户 |
| 中英混说 | **保持原样**，不要翻译；仅在明显是同一概念的重复表述时择一 |
| 标点 | 按语义补全句号/逗号；陈述句结尾必须有句号 |
| 断句 | 一段话 > 4 句时按主题分段 |

**不确定的地方不要瞎改**：拿不准的词保留原样并标注 `[?原词]`，让用户确认。

**④ 交付**：默认只输出清理后的文字（用代码块或引用块包住，方便用户复制）。
只有在用户要"证据/原始记录"时才附上 `evidence` 里的路径。

## 2. 输出格式

```markdown
<清理后的文字>

---
来源：`<evidence.norm_wav>` · `<transcript.engine>` · <duration> s
```

如果用户要的是"整理成文档"，则直接写入文件（问一句路径，或用用户已有的约定）。

## 3. 硬性规则

1. **绝不改写用户的意思**。删口语词可以，换词、加解释、总结都不行（除非用户明确要求"帮我总结"）。
2. **中英混说不翻译**。用户说 "I mean 就是那个 feeling" → 保持，不要变成"I mean that feeling"。
3. **保留专有名词**的原始发音拼写；如果 ASR 明显写错（人名/产品名），标注 `[?]` 而不是猜。
4. **长录音先分段**：`transcribe` 返回的 `tokens[].t0` 可用于分句；超过 60 s 的录音先按停顿切成 3–5 段再整理。
5. **`degraded: true` 时**（无时间戳/引擎回退）要告诉用户"这段转写可能不准，建议重录或分段"。
6. 用户说"照我说的原样记下来" → 跳过清理第 ③ 步，只补标点。

## 4. 常见用法

```
"把刚才说的记下来"            → record(transcribe=true) → 清理 → 输出
"这个 m4a 转成文字"           → transcribe(path=...) → 清理 → 输出
"我说的是 API 不是 a p i"     → 直接按用户指令修正，并记住这个术语
"整理成会议纪要"              → 清理 + 按议题分段 + 提炼待办（这一步才允许改写）
```

## 5. 留证

`transcribe` 已自动落盘：原始音频、16k 派生音频、`asr.json`（含 `words[]` 与 `tokens[]`）。
需要回溯"我到底怎么说的"时，用 `mcp__voice__play(path=<evidence.norm_wav>)` 播放原文。
