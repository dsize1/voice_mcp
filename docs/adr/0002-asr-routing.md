# ADR-0002: ASR 双引擎 + 语言路由 + 教学语言分级

- 状态：Accepted
- 日期：2026-11-18
- 相关：ADR-0003（模型）、ADR-0004（I/O）

## 背景

两个需求同时约束 ASR/教学编排的设计：

1. **通用语音 I/O**：既要英文（口语训练），也要中文（语音录入/听写），还要中英混说。
2. **教学语言必须随水平变化**：英语薄弱用户在"全英文教学"下会产生理解压力，实际有效做法是
   **中文讲解 + 英文示范**；水平提高后再逐步过渡到英文为主 / 全英文。

## 决策一：ASR 双引擎 + 显式路由

| 路由 | 引擎 | 理由 |
|---|---|---|
| `en` / `mixed` | **whisper-large-v3-turbo**（GPU） | 词级时间戳（发音评测的硬需求）、原生标点与数字规范化、code-switching（中英混说）表现最好 |
| `zh` | **SenseVoice-Small**（GPU/CPU 均可） | 中文 CER 更好、非自回归 ~70ms/10s、带情绪/事件标签（可辅助判断犹豫、笑声） |
| `auto`（默认） | 先用 SenseVoice 快速判语言，中文走 SenseVoice，其余走 whisper | 省一次 whisper 推理 |

> **P0 实测更正（2026-11-18）**：sherpa-onnx 下的 SenseVoice **会返回 token 级时间戳**
> （`OfflineRecognizerResult.timestamps` 有值，6.08s 音频得到 8 个 token 时间点，RTF 0.013）。
> 因此「SenseVoice 无时间戳所以不能做英文评测」这条假设不成立：
> 英文通道可以先用 SenseVoice 拿到粗对齐，whisper 的角色从「唯一时间戳来源」降级为「精度/标点增强」，
> 这也让 GPU EP 变成非阻塞项（见 ADR-0005 G3）。

**路由规则（写入 CONTRACT.md）**：

- 入参 `lang` 允许 `auto | en | zh | mixed`；默认 `auto`。
- `auto` 判定：SenseVoice 输出的 `lang` 标签置信度 >0.8 且为 `zh` → 中文通道；否则走 whisper。
- 训练场景（跟读/独白）**强制 `en`**，避免中文通道吞掉发音细节，并保证 `words[]` 时间戳存在。
- 中英混说（如 "I mean, 就是那种 feeling"）走 whisper，转写保留原文语言切换，**不做翻译**（翻译由 LLM 负责）。

**降级链**：whisper GPU 失败 → whisper CPU → SenseVoice（此时 `words` 可能为空，评测自动降级为整句级，`degraded: true`）。

## 决策二：教学语言分级（Teaching Language Ladder）

学习者档案 `learner.json` 中维护 `teaching_lang: "zh" | "zh-en" | "en-heavy" | "en"`，Skill 据此决定"讲解用什么语言、示范用什么形式"：

| 档位 | 触发（估计 band / 自评） | 讲解 | 示范 | 单次反馈量 |
|---|---|---|---|---|
| **L1 全中文** | < 5.0 / 明显薄弱 | 100% 中文，术语给英文+音标 | 单词级 + 慢速 110 wpm，逐词跟读 | 1 个问题 |
| **L2 中文为主** | 5.0–5.5 | 中文讲解，关键术语用英文 | 短语级，慢速→正常各一遍 | 1–2 个问题 |
| **L3 英文为主** | 6.0–6.5 | 英文讲解，中文括号兜底 | 整句示范，正常语速 | 2–3 个问题 |
| **L4 全英文** | ≥ 7.0 | 100% 英文 | 整句/整段，含语速变化 | 2–3 个问题（偏重韵律与连贯） |

升降档规则（写进 Skill，不由 MCP 决定）：

- 同一素材连续 3 次达标 → 升档候选；升级时**先保留一周"讲解语言回调"**（可随时说"用中文"）。
- 单次训练出现 ≥3 处未达标的可理解度问题 → 降一档，并把素材难度下调（更短句子、更高频词）。
- 用户显式指令优先（`用中文讲` / `just English`），立即生效并写入档案。

## 决策三：TTS 侧强制"讲解与示范分离"

Kokoro 是单语模型，**不能一句里中英混说**。因此工程上定一条硬规则：

> **一段 TTS 文本只允许一种语言。** 中文讲解与英文示范必须拆成两次 `synthesize` 调用，再由播放层顺序拼接。

- 中文讲解的音频是**可选的**：TUI 里文字讲解已经够用，默认 `play_speech=false`，只在用户说"读给我听"时才合成。
- 英文示范音是**必须的**，且每句示范同时生成两版：`speed=0.75`（慢速）与 `speed=1.0`（常速），都落盘留证。
- 中英混说（真实语流示范）留到 P4 用 CosyVoice2，不作为 P1–P3 的依赖。

## 后果

- ✅ 中文语音录入与英文口语训练共用一套服务，符合"通用工具"定位。
- ✅ 薄弱用户不必在"听不懂反馈"和"练发音"之间二选一。
- ⚠️ 双引擎 = 双份显存与双份启动时间（约 +1.5 GB，<3s），可接受。
- ⚠️ 语言路由判错会导致 `words[]` 缺失 → 必须显式暴露 `degraded` 与 `asr_engine` 字段，便于 Skill 调整措辞（例如"这次只能判断漏读的词，音素级需要重录"）。
